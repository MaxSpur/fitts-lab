Classroom analysis and public overview

The instructor and public pages share exactly the same dashboard, report, and statistical code. The combined acquisition-time plot is the default; Layout → Separate stages is an optional comparison with shared scales.

Fitted means and uncertainty

Faint points retain raw first attempts; stage/input-specific lines show descriptive weighted regressions. Shading is a pointwise 95% participant-cluster bootstrap interval for the fitted mean, not the scatter of individual clicks and not a simultaneous confidence band. Selecting a run overlays its descriptive line and latest 12 raw trajectories.

Each participant has total weight one within a task/input group. The 2,000 resamples select entire participants, retaining their repeated clicks and runs. A repeated run cannot create a new independent person. Fits remain separate by task, protocol, cursor mode, recorded device, gain, perturbation and jitter. Fewer than four participants yields no displayed population interval; four to seven is flagged as a small sample.

Paired boundary analysis

Menu and Window are separate. Free/edge run means appear on the left. The right-hand forest plot has one row per participant, small individual-run diamonds, a participant mean, and a class mean with a bootstrap interval. Positive free minus bounded indicates time saved by the boundary. Accuracy uses first-attempt miss-rate reductions in percentage points.

Matching is within participant/run and identical input/protocol settings, using control approaches only. A usable timing pair has at least one retained successful first attempt on each side; it does not imply the whole exercise was completed. Repeat pair differences are averaged within participant before the equal-participant classroom estimate. Accuracy retains all first attempts irrespective of timing cutoff.

Scientific report and limitations

The generated report compares the untrimmed reference with the current cutoff, reports sample sizes and coefficients/intervals, paired timing and accuracy differences, individual slopes, log-time sensitivity, methods and limitations. Cutoffs and live inspection are exploratory. Free always precedes bounded, so observed differences include possible practice/order effects. Browser credentials are participant identities rather than a verified roster. Hardware and physical scaling are uncontrolled. No causal boundary claim, p-value, mixed-effects model or standardized throughput score is asserted.

Read-only overview

An instructor may publish one current or historical session per slug. The landing page then shows View class results. Viewing requires no login or joining and creates no participant. The raw measurement UUIDs and pointer trajectories are retained. Credentials and instructor Auth ownership are excluded.

Public reads use a separate results service and permission-checked SQL snapshot. Existing table permissions, collection API and private Realtime are unchanged. Publishing another session replaces the previous one. Unpublishing denies future snapshots, and the viewer clears on its next check. Downloaded copies cannot be recalled. Polling is every ten seconds while visible.

Backend activation

A Pages deployment alone cannot activate publication. The new frontend fails closed until the backend exists.

  1. Apply supabase/migrations/202609290002_public_results.sql once in the existing Supabase project's SQL Editor. Do not rerun the original schema. Existing sessions remain unchanged and unpublished.
  2. Deploy the new function from this repository:
supabase functions deploy results-api --project-ref qzlzetebjbytxamzhliq --no-verify-jwt

It uses existing ALLOWED_ORIGINS, SUPABASE_URL, and the injected service-role key or existing SERVER_SECRET_KEY. Server credentials belong only in Supabase. Platform JWT verification is disabled for public reads; publication writes independently verify instructor authorization and ownership.

Reload the instructor page, choose the session, and press Publish this session. The landing-page link appears within twenty seconds. Test publication and revocation from a signed-out browser. The existing classroom-api and participant protocol require no redeployment.
